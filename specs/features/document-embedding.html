document-embedding

Pipeline step 6: turn each relabeled record into the Full and B2 texts (CC-4) with an experience level, and embed them into unit-normalized document vectors that two-way retrieval multiplies.

Status: draftUpdated: 2026-11-07Pipeline step: 6Master: architecture.html
document-embedding

Goal

Matching compares resumes and postings in one vector space (ADR-4), so both sides must be written down in exactly the same form. This feature builds, per source, a documents table from the relabeled records (cluster-relabeling): title, an experience level (listed for postings, derived from years of experience for resumes), the final skill set, and two serialized texts. text_full groups skills under cluster names (Front-end: Vue, CSS; Cloud: AWS; Other: Excel); text_b2 is the same title, level and skills with no cluster labels, so the B2 versus Full gap measures only the taxonomy (ADR-5). Each text is embedded with the configured EmbeddingClient (embedding-client; Qwen3-Embedding-4B locally by default) into L2-normalized float32 vectors (CC-5), saved with the identity of the model, the taxonomy, the alias table, and the relabel mode, and with a hash of the texts so retrieval can refuse stale or mixed inputs. The table also carries everything the B1+ baseline needs (final skills, title, level rank), so retrieval needs no other input. The build step (texts only) needs no model and runs offline; the embed step is user-run on the GPU. Defaults point at the trial tree (100 + 100 records).

Scope

In scope

  • getwork.docembed: level resolution (levels.py), the two serializers (serialize.py), the documents table and its provenance checks (documents.py), document vectors (vectors.py), and the doc-embed command with subcommands build and embed, a runbook, and a user-run checklist.
  • Reading the listed experience level of postings from data/processed/postings/postings_clean.parquet (read only).

Out of scope

  • Top-k retrieval, scoring, and B1+ (two-way-retrieval).
  • Running the real model: tests use FakeEmbeddingClient; the GPU run is user-run.
  • Embedding single skills (that is skill-taxonomy, a different space).
  • Content beyond title, level, and skills (experience entries, education, free text), as CC-4 specifies.
  • Query-time embedding of a new document (the same functions apply; wiring is a later app feature, Q-1).

Design

Two deterministic text steps, then one embedding step. doc-embed build reads the relabeled files and writes the documents table; doc-embed embed reads the table and writes one vector set per source and system. Cites ADR-4, ADR-5, ADR-7, ADR-12, ADR-14, CC-4, CC-5, CC-6, CC-11, CC-12, CC-15, CC-16. Requires cluster-relabeling T-6 (read_relabeled), skill-taxonomy T-2 (Taxonomy), embedding-client T-2 to T-4 (cache, store, factory), and alias-table T-1, T-2 (paths, fileio).

Decisions

IdDecisionRationaleAlternative not taken
DE-1Text format. Full: Title: {title}, newline, Level: {level}, newline, Skills: {Cluster A}: s1, s2; {Cluster B}: s3; Other: s4. B2: the same first two lines and Skills: s1, s2, s3, s4. A missing title or level prints Not specified; no skills prints Skills: none. Whitespace inside any field is collapsed to single spaces. Groups are ordered by taxonomy cluster id with Other last; skills inside a group keep the final skill set's order. Constant SERIALIZATION_VERSION = "ser_v1".CC-4. Labeled field lines are cheap, unambiguous for the model, and identical for both systems. Cluster ids give a deterministic, taxonomy-defined order.Prose sentences; ordering groups by size (changes whenever one skill changes).
DE-2B2 is the Full text with the cluster labels and group separators removed, so its skills appear in the same grouped order (--b2-order grouped, default). The alternative --b2-order record keeps the record's own skill order. The choice is stored in the summary and the vector meta and must match across sources.ADR-5 says "identical text without the labels". Grouped order still lets adjacency carry some cluster information to B2, which slightly favors B2; Q-10 asks the user to choose.Making record order the only mode (cleanest ablation but not "identical text").
DE-3Experience level (resolves Q-3 as a proposal). The scale is LinkedIn's: Internship, Entry level, Associate, Mid-Senior level, Director, Executive, plus Not specified. Postings use the listed level (level_source: "listed"); when absent (28% of postings) or unrecognized, the level derives from the posting's years_experience like resumes ("years"); if that is also missing, Not specified ("missing"). Resumes always derive from years_experience with bands: below 2 years Entry level, 2 up to 5 Associate, 5 or more Mid-Senior level (--level-bands 2,5). Internship, Director, Executive are never derived from years.Years cannot distinguish a director from a senior engineer, so the derived scale stops at Mid-Senior; the bands are the usual LinkedIn conventions. The bands live in DEFAULT_BANDS and a flag, so a different answer to Q-3 is a one-line change.Deriving Director/Executive from title keywords (a second heuristic that needs its own validation).
DE-4Level rank for B1+ is the index in the six-level scale (0 to 5); Not specified has no rank. Retrieval consumes level and calls level_rank.Keeps scale knowledge in one module.Storing ranks in the table (a second source of truth).
DE-5No retrieval instruction prefix: documents on both sides are embedded as plain text with the same call. This extends embedding-client E-4's no-prefix rule for skills to documents.Symmetric two-way retrieval needs one space; a query instruction would make resume vectors differ in kind from posting vectors.Qwen3's recommended instruct prefix for queries (asymmetric; could be an experiment later).
DE-6Both systems are embedded in one pass with the same client and settings and the same cache directory (documents/<source>/_embed_cache). A vector set is named <source>_full or <source>_b2 (system ids from CC-6, lower-cased for file names).Resumable, and the chunk cache is keyed by model identity plus text hash (embedding-client), so reruns and repeated texts are free.Separate runs per system.
DE-7Provenance and comparability. Every documents summary and vector meta carries alias_table_version, taxonomy_version, relabel_mode, relabel_model, relabel_backend, serialization_version, level_bands, b2_order. Two sources are comparable only if all are equal and, for vectors, the embedding identity (model, backend, dim) is equal. check_comparable and check_vector_sets_comparable raise DocEmbedMismatchError (or EmbeddingMismatchError) naming the fields. Vector metas also store texts_hash; check_vectors_current refuses vectors whose hash differs from the current table.One shared space needs one model, one taxonomy and one serialization for both sides; hashes make stale vectors detectable (the content-version rule of CC-12).Trusting file locations.
DE-8Failures: build and embed fail as a whole (exit 2 for configuration or input problems, exit 3 for embedding errors) and write nothing partial; vectors are written only after every chunk of a system is embedded, and the chunk cache lets a rerun resume.A vector set with missing rows is worse than none; there is no per-document failure mode in a deterministic embedding.Skipping failed documents.

# src/getwork/docembed/levels.py   (no third-party imports)
LEVELS: tuple[str, ...] = ("Internship", "Entry level", "Associate", "Mid-Senior level", "Director", "Executive")
NOT_SPECIFIED: str = "Not specified"
LEVEL_SOURCES: tuple[str, ...] = ("listed", "years", "missing")
DEFAULT_BANDS: tuple[float, float] = (2.0, 5.0)
def level_rank(level: str) -> int | None:
    """Index of level in LEVELS, None for NOT_SPECIFIED or anything else."""
def normalize_listed_level(raw: object) -> str | None:
    """Strip and compare case-insensitively with LEVELS; "Mid-Senior" (without "level") also maps to
    "Mid-Senior level" and "Entry" to "Entry level". A non-string (including float NaN), blank or unrecognized
    value gives None."""
def level_from_years(years: float | None, bands: tuple[float, float] = DEFAULT_BANDS) -> str | None:
    """None for None, NaN or negative. years < bands[0] -> "Entry level"; years < bands[1] -> "Associate";
    otherwise "Mid-Senior level"."""
def parse_bands(text: str) -> tuple[float, float]:
    """"2,5" -> (2.0, 5.0). ValueError unless two comma-separated numbers with 0 < first < second."""
def resolve_level(source: str, listed_raw: object, years: float | None,
                  bands: tuple[float, float] = DEFAULT_BANDS) -> tuple[str, str]:
    """Returns (level, level_source). source "resumes": ignore listed_raw; years-derived -> (level, "years"),
    else (NOT_SPECIFIED, "missing"). source "postings": normalize_listed_level(listed_raw) -> (level, "listed");
    else years-derived -> (level, "years"); else (NOT_SPECIFIED, "missing"). ValueError for another source."""

# src/getwork/docembed/serialize.py   (no third-party imports)
SERIALIZATION_VERSION: str = "ser_v1"
B2_ORDERS: tuple[str, ...] = ("grouped", "record")
def clean_field(text: str | None) -> str:
    """Collapse all whitespace runs (including newlines) to one space and strip; None or blank gives NOT_SPECIFIED."""
def group_skills(skill_clusters: Sequence[Mapping[str, str]], cluster_order: Sequence[str]) -> list[tuple[str, list[str]]]:
    """skill_clusters items have "skill" and "cluster" (CC-15). Groups in cluster_order, then OTHER last; a group
    appears only if it has skills; skills inside a group keep input order. ValueError naming the cluster if an
    item's cluster is neither in cluster_order nor OTHER."""
def serialize_full(title: str | None, level: str, skill_clusters: Sequence[Mapping[str, str]],
                   cluster_order: Sequence[str]) -> str:
    """f"Title: {clean_field(title)}\nLevel: {clean_field(level)}\nSkills: " + "; ".join(f"{name}: {', '.join(skills)}"
    for name, skills in group_skills(...)) ; "none" when there are no skills. Each skill passes through clean_field's
    whitespace collapsing (a blank skill is skipped)."""
def serialize_b2(title: str | None, level: str, skill_clusters: Sequence[Mapping[str, str]],
                 cluster_order: Sequence[str], order: str = "grouped") -> str:
    """Same first two lines; "Skills: " + ", ".join(skills) with skills in the grouped order (order "grouped") or
    the input order (order "record"), "none" when empty. ValueError for an order not in B2_ORDERS."""

Commands and outputs

  • doc-embed build [--source resumes|postings|both] [--artifacts-dir artifacts_trial] [--processed-dir data/processed] [--level-bands 2,5] [--b2-order grouped|record]. Reads taxonomy/taxonomy.json, relabeled/<source>/<source>_relabeled.jsonl, and for postings the id and experience_level columns of the cleaned Parquet. Needs no embedding settings. Writes documents/<source>/<source>_documents.jsonl, .parquet, _summary.json. Default source is both. Errors (exit 2): a missing taxonomy (message contains taxonomy build) or relabeled file (contains relabel), relabeled records whose alias table or taxonomy version differs from the files, the two sources having different relabel modes, models, or backends, invalid bands. All are detected before any output is written. A missing posting Parquet is not an error: levels fall back to years and a note goes to stderr.
  • doc-embed embed [--source both] [--artifacts-dir artifacts_trial] [--chunk-size 256] [--no-cache] plus the shared embedding options (--embed-backend --embed-model --device --dtype --embed-batch-size --max-seq-length --env-file, from add_embed_args). Reads the documents tables and summaries; writes documents/<source>/<source>_full.npy, _full_ids.json, _full_meta.json and the same three for _b2, and chunk caches under documents/<source>/_embed_cache/. Errors: a missing documents table or summary (message contains doc-embed build), incomparable summaries across the two sources, configuration errors (exit 2), an EmbeddingError (exit 3, already cached chunks kept).
  • Output is deterministic for the same inputs (documents files byte-identical on rerun; vectors identical with the same model on the same device up to numerical noise).
  • Both commands print one JSON summary per source to stdout.
