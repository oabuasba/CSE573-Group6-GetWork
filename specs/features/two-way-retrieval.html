two-way-retrieval

Pipeline step 7: for each system (B1+, B2, Full) rank postings for every resume and resumes for every posting, exactly and deterministically, and save the ranked lists that evaluation pools and judges.

Status: draftUpdated: 2026-11-07Pipeline step: 7Master: architecture.html
two-way-retrieval

Goal

This is the last build stage before evaluation. For the two embedding systems it scores every pair with the inner product of unit vectors, S = R̂Ĵᵀ (ADR-7, CC-5), computed in row blocks so the full resume-by-posting matrix never has to fit in memory, and takes the top-k postings for each resume (row of S) and the top-k resumes for each posting (column of S). For B1+ (ADR-8) it scores every pair with a weighted sum of skill Jaccard over the final skill sets, title token overlap, and ordinal seniority similarity, using sparse incidence matrices so the same blockwise top-k applies. Ties break by document position, so results are exact and reproducible. The outputs are six long-format Parquet files (3 systems × 2 directions) with the system id, query id, rank, document id and score, plus a summary that records the identity of everything they came from. A show command prints one query's matches next to their titles and levels for manual inspection. Before scoring, the stage proves the inputs belong together: both document tables and both vector sets come from the same taxonomy, relabel mode, serialization and embedding model, and the vectors match the current texts. Defaults point at the trial tree.

Scope

In scope

  • getwork.retrieval: blockwise exact top-k (topk.py), the B1+ scorer, weights, and the weight-grid helper (b1plus.py), loading and checking inputs (inputs.py), scoring plans and the run (run.py), reading rankings and single-query lookup (query.py), and the retrieve command with subcommands run and show, a runbook, and a user-run checklist.

Out of scope

  • Tuning the B1+ weights: it needs judge labels and a metric (eval stages). This feature supplies the formula, the default weights, grid_search_weights, and --weights/--weights-file to apply the tuned values.
  • Sampling, pooling, blind pair sets (eval-sampling-pooling), judging, metrics, the explanation agent, and the web app.
  • Approximate-nearest-neighbor indexes or a vector database (ADR-7 rejects them).
  • Embedding anything: vectors come from document-embedding.

Design

All three systems are reduced to one shape: a scoring plan that can produce the scores of a block of queries against all documents, and one generic function that turns a plan into exact top-k lists. Cites ADR-7, ADR-8, ADR-12, CC-5, CC-6, CC-11, CC-17. Requires document-embedding T-1, T-4, T-5, alias-table T-2, T-4, and skill-taxonomy T-1 (adds scipy).

Decisions

IdDecisionRationaleAlternative not taken
RT-1Both directions use the same plan machinery. "resume_to_posting" ranks postings for each resume (queries = resumes); "posting_to_resume" ranks resumes for each posting. For embeddings the second direction computes Ĵ R̂ᵀ, which is the transpose of S, so column l of S equals row l of that product.One code path and the block structure bounds memory: 28,842 × 8,423 float32 is 0.9 GB if materialized; a 512-row block is 17 MB.Materializing S once; separate code for columns.
RT-2Top-k is exact with deterministic ties: for each query, documents are ordered by score descending and, for equal scores, by document position ascending (a stable sort of the negated scores). k larger than the number of documents is clipped. Default k = 10 (the pool depth in ADR-9).Reproducible rankings that tests can compare exactly; ADR-7 (exact, deterministic).Partial selection (argpartition) without a tie rule.
RT-3B1+ formula (proposal for Q-2): score = w_s·J_skills + w_t·J_title + w_l·L. J_skills is the Jaccard index of the two documents' final skill sets compared by normalize_key (0 if both are empty). J_title is the Jaccard index of title token sets (lower-cased; tokens are runs matching [a-z0-9][a-z0-9#+.]* with trailing dots removed; the stop words a an and at for in of or the to with removed; 0 if both are empty). L = 1 − |rank_r − rank_j| / 5 using level_rank, and 0.5 when either level is unspecified. Weights are non-negative and sum to 1; default (0.7, 0.15, 0.15) until tuned.Each term is a standard, explainable lexical signal over exactly the inputs the embedding systems see (ADR-8); an ordinal level distance rewards near matches. The neutral 0.5 keeps documents with an unknown level from being punished or favored. The defaults put the weight on skills, as in the proposal's B1.Exact-match seniority only; BM25 or TF-IDF titles (more machinery, no payoff for short titles).
RT-4B1+ is computed with SciPy sparse matrices: binary skill and title-token incidence matrices over a vocabulary shared by both sides, intersections from a sparse product per query block, unions from set sizes. Levels enter as a rank vector with NaN for unspecified.A Python double loop over 243 million pairs is infeasible for the full corpus; the sparse product is exact.Dense incidence matrices (too large); a Python loop.
RT-5Weight search is a pure helper: grid_search_weights(objective, step) enumerates every non-negative triple on the simplex with the given step, calls objective(weights) (higher is better), and returns the best; ties go to the earlier candidate in the enumeration order (higher skill weight first, then higher title weight). The objective (e.g. dev-set nDCG@10) is supplied by the evaluation stages.Keeps this feature free of labels and metrics while making the tuning step a one-liner later.Hard-coding a tuning loop that needs labels.
RT-6Input checks happen before any scoring and apply to the embedding systems only where relevant: the two documents summaries must be comparable (check_comparable); for Full and B2, each vector set's texts_hash must match the current table (check_vectors_current), its ids must equal the table's ids in order, and the resume set and posting set must pass check_vector_sets_comparable. B1+ needs only the documents tables, so --systems B1+ works before any embedding was run.The shared-space requirement of ADR-4 and CC-12's version rule, enforced where the vectors are consumed.Trusting file names.
RT-7Rankings are stored long-format: columns system, direction, query_id, rank (1-based), doc_id, score, rows ordered by numeric query id then rank. File names use a slug for the system (b1plus, b2, full) because + is awkward in file names; the system column holds the CC-6 id.Easy to load with pandas and to pool; the system name stays inside the data, not only the file name. Blind labeling is applied later by the pooling feature, which drops this column.One file per query; JSON.

# src/getwork/retrieval/topk.py   (numpy only)
def similarity_matrix(resume_vectors: np.ndarray, posting_vectors: np.ndarray) -> np.ndarray:
    """S = R @ J.T as float32, shape (m, n). ValueError unless both are 2-D float32 with equal width.
    For small inputs and tests; the run never calls it."""
def topk_from_blocks(block: Callable[[int, int], np.ndarray], n_queries: int, n_docs: int, k: int,
                     block_size: int = 512) -> tuple[np.ndarray, np.ndarray]:
    """ValueError if k < 1, block_size < 1, or n_docs < 1. k_eff = min(k, n_docs). For start in range(0, n_queries,
    block_size): scores = block(start, min(start + block_size, n_queries)) (shape (rows, n_docs), ValueError if the
    shape is wrong); order = np.argsort(-scores, axis=1, kind="stable")[:, :k_eff]. Returns (indices int32,
    scores float32), both shape (n_queries, k_eff), the scores gathered from `scores` in that order. n_queries == 0
    returns two empty (0, k_eff) arrays."""
def matrix_block(queries: np.ndarray, docs: np.ndarray) -> Callable[[int, int], np.ndarray]:
    """block(start, stop) = queries[start:stop] @ docs.T as float32."""

# src/getwork/retrieval/b1plus.py
SENIORITY_UNKNOWN: float = 0.5
TITLE_STOPWORDS: frozenset[str] = frozenset({"a", "an", "and", "at", "for", "in", "of", "or", "the", "to", "with"})
@dataclass(frozen=True)
class B1PlusWeights:
    skills: float
    title: float
    level: float
    def __post_init__(self) -> None:
        """ValueError if a weight is negative or not finite, or if the sum differs from 1 by more than 1e-6."""
    def as_dict(self) -> dict[str, float]: ...        # {"skills", "title", "level"}
DEFAULT_WEIGHTS: B1PlusWeights = B1PlusWeights(0.7, 0.15, 0.15)
def parse_weights(text: str) -> B1PlusWeights:
    """"0.7,0.15,0.15" -> B1PlusWeights(skills, title, level). ValueError unless exactly three numbers."""
def load_weights(path: Path) -> B1PlusWeights:
    """JSON object with exactly the keys skills, title, level; FileNotFoundError naming the path; ValueError
    (naming the path) for bad JSON, missing or extra keys, or invalid values."""
def title_tokens(title: str | None) -> frozenset[str]:
    """RT-3 tokenization; None or blank gives an empty set."""
def jaccard(a: AbstractSet[str], b: AbstractSet[str]) -> float:
    """|a ∩ b| / |a ∪ b|, 0.0 when both are empty."""
def skill_keys(skills: Sequence[str]) -> frozenset[str]:
    """frozenset of normalize_key(s) for s in skills, empty keys dropped."""
def seniority_similarity(level_a: str, level_b: str) -> float:
    """SENIORITY_UNKNOWN if either level has no rank; else 1 - abs(rank_a - rank_b) / (len(LEVELS) - 1)."""
def b1plus_score(resume_doc: Mapping[str, object], posting_doc: Mapping[str, object], w: B1PlusWeights) -> float:
    """Reference implementation on two documents-table rows ("skills", "title", "level"):
    w.skills * jaccard(skill_keys) + w.title * jaccard(title_tokens) + w.level * seniority_similarity."""
def grid_search_weights(objective: Callable[[B1PlusWeights], float], step: float = 0.05) -> tuple[B1PlusWeights, float]:
    """ValueError unless 0 < step <= 0.5 and 1/step is within 1e-9 of an integer. Candidates: for i in range(N, -1, -1)
    for j in range(N - i, -1, -1) with N = round(1/step): weights (i*step, j*step, (N-i-j)*step) rounded to 10
    decimals. Returns (best weights, best objective); the first candidate wins ties."""
@dataclass(frozen=True)
class B1Features:
    ids: list[str]
    skills: "scipy.sparse.csr_matrix"      # (n, V) float32 0/1
    skill_counts: np.ndarray               # (n,) float32
    titles: "scipy.sparse.csr_matrix"      # (n, T) float32 0/1
    title_counts: np.ndarray               # (n,) float32
    ranks: np.ndarray                      # (n,) float32, NaN when the level is unspecified
def build_features(resume_docs: Mapping[str, Mapping[str, object]],
                   posting_docs: Mapping[str, Mapping[str, object]]) -> tuple[B1Features, B1Features]:
    """Shared skill and title vocabularies over both sides (sorted for determinism); ids in the dicts' order."""
def b1plus_block(q: B1Features, d: B1Features, start: int, stop: int, w: B1PlusWeights) -> np.ndarray:
    """float32 (stop - start, len(d.ids)): w.skills * J_skills + w.title * J_title + w.level * L, where
    J = inter / (count_q + count_d - inter) (0 where the union is 0), inter from (q.skills[start:stop] @ d.skills.T)
    .toarray() (titles: q.titles / d.titles), and L = 1 - abs(rank_q - rank_d)/5 with SENIORITY_UNKNOWN wherever either rank is NaN. Equal, up to
    1e-6, to b1plus_score on the same pair."""

Commands and outputs

  • retrieve run [--artifacts-dir artifacts_trial] [--systems all|B1+,B2,Full] [--k 10] [--weights 0.7,0.15,0.15 | --weights-file PATH] [--block-size 512]. Reads the documents tables, summaries and vector sets under documents/; writes retrieval/topk_{b1plus,b2,full}_{resume_to_posting,posting_to_resume}.parquet and retrieval/retrieval_summary.json. Errors (exit 2, nothing written): missing documents or vectors (messages contain doc-embed build or doc-embed embed), any mismatch of RT-6 (message names the keys), invalid --k, weights or systems. Prints the summary as JSON.
  • retrieve show --direction resume_to_posting|posting_to_resume --id ID [--system B1+|B2|Full] [--k 5] [--artifacts-dir artifacts_trial] [--weights ...]. Loads the inputs for that system, computes the single query (no dependence on the Parquet files), and prints the query's title, level, and skills, then one line per match: rank, score (4 decimals), id, level, title, and the skills shared with the query (at most 8). Default system Full. An unknown id is exit 2.
  • Reruns give identical table contents. The embedding systems' scores equal the matrix product on the stored vectors to float32 precision.

def similarity_matrix(resume_vectors: np.ndarray, posting_vectors: np.ndarray) -> np.ndarray:
    """S = R @ J.T as float32, shape (m, n). ValueError unless both are 2-D float32 with equal width.
    For small inputs and tests; the run never calls it."""
def topk_from_blocks(block: Callable[[int, int], np.ndarray], n_queries: int, n_docs: int, k: int,
                     block_size: int = 512) -> tuple[np.ndarray, np.ndarray]:
    """ValueError if k < 1, block_size < 1, or n_docs < 1. k_eff = min(k, n_docs). For start in range(0, n_queries,
    block_size): scores = block(start, min(start + block_size, n_queries)) (shape (rows, n_docs), ValueError if the
    shape is wrong); order = np.argsort(-scores, axis=1, kind="stable")[:, :k_eff]. Returns (indices int32,
    scores float32), both shape (n_queries, k_eff), the scores gathered from `scores` in that order. n_queries == 0

    """block(start, stop) = queries[start:stop] @ docs.T as float32."""

class B1PlusWeights:
    skills: float
    title: float
    level: float
    def __post_init__(self) -> None:
        """ValueError if a weight is negative or not finite, or if the sum differs from 1 by more than 1e-6."""
    def as_dict(self) -> dict[str, float]: ...        # {"skills", "title", "level"}
DEFAULT_WEIGHTS: B1PlusWeights = B1PlusWeights(0.7, 0.15, 0.15)
def parse_weights(text: str) -> B1PlusWeights:
    """"0.7,0.15,0.15" -> B1PlusWeights(skills, title, level). ValueError unless exactly three numbers."""
def load_weights(path: Path) -> B1PlusWeights:
    """JSON object with exactly the keys skills, title, level; FileNotFoundError naming the path; ValueError
    (naming the path) for bad JSON, missing or extra keys, or invalid values."""
def title_tokens(title: str | None) -> frozenset[str]:
    """RT-3 tokenization; None or blank gives an empty set."""
def jaccard(a: AbstractSet[str], b: AbstractSet[str]) -> float:
    """|a ∩ b| / |a ∪ b|, 0.0 when both are empty."""
def skill_keys(skills: Sequence[str]) -> frozenset[str]:
    """frozenset of normalize_key(s) for s in skills, empty keys dropped."""

    """SENIORITY_UNKNOWN if either level has no rank; else 1 - abs(rank_a - rank_b) / (len(LEVELS) - 1)."""
def b1plus_score(resume_doc: Mapping[str, object], posting_doc: Mapping[str, object], w: B1PlusWeights) -> float:
    """Reference implementation on two documents-table rows ("skills", "title", "level"):
    w.skills * jaccard(skill_keys) + w.title * jaccard(title_tokens) + w.level * seniority_similarity."""
def grid_search_weights(objective: Callable[[B1PlusWeights], float], step: float = 0.05) -> tuple[B1PlusWeights, float]:
    """ValueError unless 0 < step <= 0.5 and 1/step is within 1e-9 of an integer. Candidates: for i in range(N, -1, -1)
    for j in range(N - i, -1, -1) with N = round(1/step): weights (i*step, j*step, (N-i-j)*step) rounded to 10
    decimals. Returns (best weights, best objective); the first candidate wins ties."""

Instructions: Standard library plus getwork.docembed.levels and getwork.alias.normalize. Title regex [a-z0-9][a-z0-9#+.]* on the casefold()-ed title, then rstrip(".") on each token and drop empty tokens and stop words. Step 0.7 fails the "1/step is an integer" rule (1/0.7 = 1.4286), step 0.3 too; step 0.1 gives N = 10 and 66 candidates; the weights built from i*step must sum to 1 within the 1e-6 tolerance of B1PlusWeights (use rounding to 10 decimals as specified). The AC-3 assertion about jaccard uses concrete sets: {"a","b"} vs {"b","c","d"} gives 1/4 = 0.25.

# src/getwork/retrieval/b1plus.py   (this task)
@dataclass(frozen=True)
class B1Features:
    ids: list[str]
    skills: "scipy.sparse.csr_matrix"      # (n, V) float32 0/1
    skill_counts: np.ndarray               # (n,) float32
    titles: "scipy.sparse.csr_matrix"      # (n, T) float32 0/1
    title_counts: np.ndarray               # (n,) float32
    ranks: np.ndarray                      # (n,) float32, NaN when the level is unspecified
def build_features(resume_docs: Mapping[str, Mapping[str, object]],
                   posting_docs: Mapping[str, Mapping[str, object]]) -> tuple[B1Features, B1Features]:
    """Shared skill and title vocabularies over both sides (sorted for determinism); ids in the dicts' order."""
def b1plus_block(q: B1Features, d: B1Features, start: int, stop: int, w: B1PlusWeights) -> np.ndarray:
    """float32 (stop - start, len(d.ids)): w.skills * J_skills + w.title * J_title + w.level * L, where
    J = inter / (count_q + count_d - inter) (0 where the union is 0), inter from (q.skills[start:stop] @ d.skills.T)
    .toarray() (titles: q.titles / d.titles), and L = 1 - abs(rank_q - rank_d)/5 with SENIORITY_UNKNOWN wherever either rank is NaN. Equal, up to
    1e-6, to b1plus_score on the same pair."""

Instructions: Import scipy at module level (import scipy.sparse as sp); the retrieval package may import scipy and numpy only (no torch). Build the incidence matrices with sp.csr_matrix((data, (rows, cols)), shape=..., dtype=np.float32); the counts are the row sums (they equal the set sizes because keys are sets). Ranks come from level_rank(doc["level"]), np.nan for None. Use np.divide(inter, union, out=np.zeros_like(inter), where=union > 0) to avoid division warnings. Test data: the synthetic documents described in AC-5, written as plain dicts with skills, title, level keys.

Open questions

Assumptions and items for the user to confirm
  • Assumed, answers Q-2 as a proposal: title overlap is token Jaccard (with a small stop-word list); seniority is ordinal distance over the six-level scale with a neutral 0.5 when unknown; the weight search is a simplex grid with step 0.05 against a dev-set objective supplied later; defaults (0.7, 0.15, 0.15). Confirm or change the formula before the dev stage; only b1plus.py changes. Note that B1+ seniority uses the same derived resume levels as the embedding systems (document-embedding DE-3), so the three systems see identical inputs, as ADR-8 requires.
  • Assumed: default k = 10 (pool depth of ADR-9). The evaluation stages may rerun with a larger --k; no other change is needed.
  • Assumed: there is no minimum-score cutoff and no exclusion of pairs; every resume has a full ranking over all postings (the pool of the evaluation is 5,000 sampled postings; the sampling stage subsets postings before or after this stage, which is its decision, see the handoff).
  • Handoff: eval-sampling-pooling reads the six Parquet files through read_topk and pools the top-10 of B1+, B2, and Full per query, then drops the system column and shuffles (CC-8). If the 5,000-posting cap should apply before retrieval, the sampling feature must either subset the posting documents table before doc-embed embed or filter these rankings afterward; this spec does not choose, and the second option leaves rankings slightly deeper than 10 useful: run with --k larger in that case. ranking-metrics consumes the same files plus labels; taxonomy-validity uses query_matches with modified documents (re-embedded) to compute rank drops, and grid_search_weights with the dev-set nDCG@10 as objective to tune B1+; match-agent's similarity tool calls query_matches.
