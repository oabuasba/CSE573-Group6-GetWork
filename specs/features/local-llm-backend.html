local-llm-backend

Run the structurer (and every later LLM step) against a local OpenAI-compatible server hosting a Qwen model, or against Voyager, chosen by configuration.

Status: draftUpdated: 2026-11-07Pipeline step: 2 (and 5)Master: architecture.html
local-llm-backend

Goal

The structurer today can only call Voyager. The original proposal used Qwen3-8B served locally, and the user has an NVIDIA RTX 5070 (12 GB VRAM, confirmed with nvidia-smi), so the user wants to choose per run between Voyager and a model on their own GPU. This feature adds a local backend next to voyager, selected by a flag or an environment variable, with its own validated settings, safe request defaults, fast failure when the local server is down, and a backend field in every record so provenance still works across backends. It also adds one shared client factory that the structurer and the later LLM steps (alias proposal, cluster naming, unseen-skill assignment, re-extraction) all use. Agents never install or start a server, download weights, or make real calls: those are user-run checklist steps, and every test is offline.

Scope

In scope

  • An extra_body field on LLMRequest, merged into the request by the existing OpenAI-SDK adapter, and a connection_errors_fatal switch on that adapter.
  • Backend-aware settings (BackendSettings, load_backend_settings) and a shared make_client / add_llm_args in src/getwork/llm/factory.py.
  • A backend field on every structured record (appended to RECORD_KEYS, Parquet schema, summary), the provenance rule extended to it, and a default for older records that lack it.
  • Per-backend defaults for the structurer's --workers, --reasoning-effort, and response-schema options, plus --backend and --extra-body.
  • A runbook section with a user-run checklist (L-1 to L-8) for a local server, a model recommendation for 12 GB (marked inferred where it is), and .env.example and .gitignore updates.

Out of scope

  • Installing or starting vLLM, Ollama, or llama.cpp; downloading weights; running the structurer for real. All user-run.
  • A dedicated per-server client or a direct in-process vLLM/transformers client (decision L-1).
  • Remote non-HTTPS servers. http:// stays limited to localhost, 127.0.0.1 and ::1 (structurer D-17); a server on another machine needs an SSH tunnel or HTTPS.
  • Model quality evaluation and choosing the final dataset model. A full dataset must come from one model.
  • Changing the Voyager path's behavior. Existing Voyager tests must still pass unchanged apart from the explicitly listed ones.

Design

The adapter in src/getwork/llm/voyager.py already talks the OpenAI chat-completions dialect through the openai SDK, and vLLM, Ollama, and the llama.cpp server expose the same dialect plus /v1/models. So a local backend is a second configuration of that adapter, not a second adapter (L-1). What differs is settings (no key, local URL), request defaults (thinking off, schema off), error policy (a refused connection is fatal, not retried for minutes), and provenance (a backend id). This extends ADR-11 (which anticipated another backend behind LLMClient) and is recorded as ADR-13; secrets rules stay CC-10; record fields extend CC-9.

L-10Structured-output (JSON mode) differences. Voyager: response_format with a JSON schema is on by default, as today. Data flow

Selecting the backend. structurer (and each later LLM CLI) calls add_llm_args, then make_client. The result's backend, model, and secrets go into ExtractConfig / the step's config. Defaults. After parsing, the structurer resolves the unset options from the backend: workers (4 or 2), reasoning effort (none or omitted), response schema (on or off). Options the user gave explicitly are never overridden. Requests. Unchanged for voyager. For local the request has no reasoning_effort and no response_format unless the user asked, and carries extra_body from --extra-body. Errors. The status mapping is unchanged (error_from_http): a vLLM or Ollama 400 for an over-long prompt is a record failure, 5xx (Ollama "server busy" 503, runner crash 500) is transient with backoff, 404/401/403 is fatal. The only new mapping is the local connection error (L-4). There is no Retry-After on local servers; backoff then uses 5, 10, 20, 40 s. Provenance. _check_provenance compares (model, prompt_version, schema_version, backend) against the checkpoint, treating a missing backend as "voyager"; after reading the checkpoint the runner passes every record through upgrade_record so write_final (which indexes RECORD_KEYS) never fails on an old record.
