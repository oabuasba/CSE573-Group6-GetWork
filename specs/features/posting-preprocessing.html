Posting preprocessing

Reduce the 123,849 LinkedIn postings to the IT-related ones, clean and deduplicate them, and write a labeled-by-family table that structuring can read, with an audit trail of everything removed.

Status: draftUpdated: 2026-11-07Pipeline step: 1 (posting side)Master: architecture.html
posting-preprocessing

Goal

Step 1 of the pipeline (ADR-2) for the posting side. It reads data/job_postings/, keeps postings whose titles belong to the six job families that correspond to the ten resume occupations, applies the same quality rules as the resume side, removes duplicate postings, and writes a cleaned table, the untouched raw description, a drop log, a domain review sample, and a summary of counts. No LLM is involved. The domain filter is title-first with an industry check only for the ambiguous project-manager family, because the measurements below show that industry alone is a poor signal. All postings are processed: there is no sampling here, and the 5,000-posting evaluation cap belongs to eval-sampling-pooling.

Input: 3 CSVs read in place
LLM calls: none
Rows: 123,849 in
Expected kept: about 7k–9k
Output: data/processed/postings/, committed

Scope

In scope

  • Loading postings.csv and joining each posting's industry names from job_industries.csv and industries.csv.
  • The domain filter: six title families, title exclusions, and the project-manager industry/title rule.
  • Posting text cleaning that preserves paragraph structure, quality filtering (too short, corrupted, non-English) by reusing the resume feature's filter code, and deduplication.
  • Writing data/processed/postings/postings_clean.parquet, postings_raw.parquet, postings_drop_log.csv, postings_domain_review.csv, and postings_summary.json.
  • A command-line entry point, tests, and a validation test of the real outputs.

Out of scope

  • Resumes: owned by resume-preprocessing, whose scaffold (pyproject.toml, uv.lock, the src/getwork/ package) and shared modules this feature builds on. Nothing here changes those specs' interfaces.
  • The 5,000-posting cap and all sampling: eval-sampling-pooling. This feature outputs every kept posting.
  • Skill extraction, the structured record (CC-1), and inferring a missing experience level: llm-structuring. This feature keeps experience_level as given, null included.
  • Title normalization or tokenization for the B1+ title-overlap score: two-way-retrieval. This feature keeps the raw title.
  • The other CSVs (companies.csv, benefits.csv, salaries.csv, job_skills.csv, and so on).
  • How the 517 MB postings.csv is committed to git: Q-7. This feature only reads its path. The outputs it writes are small (about 8k rows).

Design

Load, filter by domain, clean, filter by quality, deduplicate, write. Each stage is a pure function on a pandas DataFrame so it can be tested on tiny fixtures. The domain filter runs first, because it removes about 92% of rows before the slower language detection. Raw descriptions are written verbatim to a separate file because the judges read raw text (ADR-9). This feature reuses the resume feature's alpha_ratio, control_ratio, detect_language (src/getwork/preprocess/text.py) and its apply_quality_filters and ResumeFilterConfig (src/getwork/preprocess/filters.py) unchanged. Despite its name, ResumeFilterConfig only carries thresholds, and apply_quality_filters only needs the columns id, text_raw, text_clean, n_words. Conventions: core contracts (repo layout, uv, Parquet).

Domain rules

These starting values are final for the first build and provisional afterward. The review sample (postings_domain_review.csv) exists so you can check precision and recall by eye. A title is matched with re.search, case-insensitive. Initial values:

DOMAIN_FAMILIES = {   # insertion order is the family order
  "software": r"software|developer|programmer|full[- ]?stack|front[- ]?end|back[- ]?end|devops|site reliability|\bsre\b|\bsdet\b|qa engineer|data engineer|machine learning engineer|(ios|android|mobile|web|cloud) engineer",
  "database": r"database (admin|administrator|engineer|developer|architect)|\bdba\b",
  "sysadmin": r"systems? (admin|administrator|engineer)|sysadmin|it support|help ?desk|desktop support|infrastructure engineer|cloud architect",
  "network":  r"network (admin|administrator|engineer|architect|technician|analyst)",
  "security": r"security (analyst|engineer|architect)|cyber|infosec|information security|soc analyst",
  "project_manager": r"project manager|program manager|scrum master",
}
TITLE_EXCLUDE = r"real estate|business developer|business development|property developer|land developer|\bsales\b|account executive|\brecruit|talent acquisition|hvac|merchandis|\bnurs"
PM_TECH_TITLE = r"\bIT\b|software|technical|technology|systems?|digital|data|application|\bERP\b|\bSAP\b|cloud|network|infrastructure|cyber|security|\bweb\b|agile|devops|\bAI\b"
TECH_INDUSTRIES = frozenset({
  "Software Development", "IT Services and IT Consulting", "IT System Custom Software Development",
  "Information Technology & Services", "Technology, Information and Internet",
  "Technology, Information and Media", "Computer and Network Security",
  "Data Security Software Products", "Desktop Computing Software Products",
  "Data Infrastructure and Analytics", "Computer Networking", "Computer Networking Products",
  "Computer Hardware", "Computer Hardware Manufacturing", "Telecommunications",
  "Internet Marketplace Platforms", "Social Networking Platforms", "Computer Games",
})

\bsales\b does not match "Salesforce Developer", which must stay in. A posting is in domain when domain_families returns at least one family.

# src/getwork/preprocess/postings.py
from pathlib import Path
import pandas as pd

def load_postings(postings_csv: Path, job_industries_csv: Path,
                  industries_csv: Path) -> tuple[pd.DataFrame, int]:
    """Read postings.csv (only the columns job_id, title, description, company_name,
    location, formatted_work_type, formatted_experience_level) as strings, without
    NA conversion. Return (df, unmapped_industry_rows).
    df columns: id (str "j-<job_id>"), job_id (str), title (str),
    company_name (str, "" if missing), location (str), work_type (str),
    experience_level (str | None; blank becomes None), industries (list[str]:
    industry names in job_industries file order, repeats removed, [] if none),
    text_raw (str, the description verbatim).
    Sorted ascending by int(job_id).
    unmapped_industry_rows: number of job_industries rows whose industry_id is not
    in industries.csv (those rows are skipped).
    Raise ValueError if job_id is not unique or a needed column is missing."""

def clean_posting_text(raw: str) -> str:
    """html.unescape; remove tags matching </?[A-Za-z][^>]*>; convert \r\n and \r to \n;
    replace "\xa0" with " "; collapse runs of spaces and tabs to one space;
    strip trailing spaces on each line; collapse 3 or more consecutive newlines to
    exactly 2; strip the whole string. Idempotent on text whose entities decode only once
    (the tested case); double-escaped entities such as "&amp;lt;" decode further on a second
    pass, so it is not idempotent in general. Keeps single and double newlines,
    "**", and all other characters."""

def add_posting_columns(df: pd.DataFrame) -> pd.DataFrame:
    """Return a copy with text_clean (str) = clean_posting_text(text_raw),
    n_chars (int) = len(text_clean), n_words (int) = len(text_clean.split())."""
# src/getwork/preprocess/posting_dedup.py
def drop_duplicate_postings(df: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame]:
    """Input has columns id, job_id, title, text_clean (plus others).
    Duplicate key = (" ".join(title.casefold().split()),
                     " ".join(text_clean.casefold().split())).
    In each group keep the row with the smallest int(job_id).
    Return (kept, dropped). kept: same columns, input row order.
    dropped: columns id, rule, detail with rule "duplicate" and
    detail "duplicate_of=<kept id>"."""

DEFAULT_DATA: Path = Path("data/job_postings")
DEFAULT_OUT: Path = Path("data/processed/postings")
REVIEW_SAMPLE_SIZE: int = 100

def main(argv: list[str] | None = None) -> int:

Outputs

File (in --out)Contents
postings_clean.parquetKept rows, sorted by int(job_id). Columns: id, job_id, title, company_name, location, work_type, experience_level (str or null), industries (list of str), families (list of str), text_clean, n_chars, n_words.
postings_raw.parquetSame kept ids, same order. Columns: id, text_raw.
postings_drop_log.csvRows removed by the quality filters and by deduplication, sorted by int(job_id) of the id. Columns: id, rule, detail. The roughly 113k not_in_domain rows are not logged individually, only counted in the summary.
postings_domain_review.csvFor eyeballing the domain filter. Columns: id, title, decision (kept or dropped), families (joined with ;), industries (joined with ;). Up to REVIEW_SAMPLE_SIZE kept rows sampled from the domain-kept rows before the quality filters, and up to REVIEW_SAMPLE_SIZE dropped rows sampled from the not_in_domain rows that have at least one industry in TECH_INDUSTRIES (these are the most likely misses). Sampling uses DataFrame.sample(n, random_state=0); if fewer rows exist, take all.
postings_summary.jsonKeys: loaded, in_domain, kept, dropped (object with all five rules, zero when none: not_in_domain, too_short, corrupted, non_english, duplicate), families (kept rows per family; a posting in two families counts in both), experience_level_null (kept rows), unmapped_industry_rows, config (the ResumeFilterConfig fields plus review_sample_size). Sorted keys, indent 2. Invariants: loaded == kept + sum(dropped.values()) and in_domain == loaded - dropped.not_in_domain.

Parquet is written with pyarrow, compression="zstd", index=False.

Acceptance criteria

Each criterion states an observable behavior and the test that proves it. Ids are stable: append new ones, and mark removed ones with <del> instead of renumbering. Run tests with uv run pytest.

  1. AC-1: domain_families returns the right families for example titles: "React Developer" in ["Construction"] gives ["software"] (industry not required); "Salesforce Developer" gives ["software"] (not excluded by \bsales\b); "DevOps / Systems Engineer" gives ["software", "sysadmin"] in that order; "Postgres Database Administrator" gives ["database"]; "Network Engineer" gives ["network"]; "Cyber Security Analyst" gives ["security"]. Test: src/tests/test_domain.py::test_title_families
  2. AC-2: Titles matching TITLE_EXCLUDE return []: "Real Estate Developer", "Business Development Manager", "Sales Engineer", "HVAC Programmer"; a title matching no family ("Registered Nurse") also returns []. Test: src/tests/test_domain.py::test_exclusions_and_non_matches
  3. AC-3: The project-manager family needs an IT signal: "Project Manager" in ["Construction"] gives []; in ["IT Services and IT Consulting"] gives ["project_manager"]; "IT Project Manager" in ["Construction"] gives ["project_manager"]; "Software Engineer" in ["Construction"] still gives ["software"]. Test: src/tests/test_domain.py::test_project_manager_needs_it_signal

Open questions

Assumptions

1. Six families, not "software only". The proposal says "software-related terms (e.g., developer, software engineer)". I widened this to the six families that match the ten resume occupations, so resumes labeled database administrator, systems administrator, network administrator, security analyst, or project manager have postings to match. The alternative, software titles only, is a one-line change in DOMAIN_FAMILIES, and would leave those five resume classes without good matches. Please confirm. 2. Project managers need an IT signal. Without it about 2,200 construction and civil-engineering project managers would pollute the pool. The title-qualifier list is provisional. 3. Duplicate key is title plus description, not including company, because the difference is only 16 postings of 10.5k in the candidate set. 4. All patterns are provisional. They come from rough prototypes on the real data, not a labeled sample. The review sample exists for you to check them, and the first real run may need a second pass. 5. Quality thresholds are reused from the resume side (min_words=50, language probability 0.90, and so on) through ResumeFilterConfig, whose name is now a small wart. Renaming it later is a mechanical change across both features. 6. The pool will exceed 5,000. I estimate 7k–9k kept, so eval-sampling-pooling will have to apply the fixed random 5,000 sample from the evaluation plan. 7. Dependencies on in-progress work. This spec relies on the resume feature's text.py, filters.py, and scaffold exactly as specified there. If those interfaces change, update this spec. 8. The raw 517 MB postings.csv: its git handling is still Q-7. 9. Experience level is not imputed here. The existing Q-3 covers the scale and the missing values.
