chat-split-layout

The chat page becomes a left/right split (conversation left, suggestion right, hideable) with a rounded, auto-growing, Claude-style composer.

Status: awaiting-approvalUpdated: 2026-11-14Pipeline step: appMaster: architecture.html
chat-split-layout

Goal

The per-match chat page (#/chat/<match id>, built in ui-polish-3) stacks everything in one column: back link, heading, a full-width suggestion card, the empty-state prompt and starter chips, and a one-line input with a grey Send button at the bottom. The user wants it to feel like a chat application. This feature (1) lays the page out as two panes, the conversation on the left and the suggestion (match card) on the right, with a button to hide the right pane so the user can focus on the chat; (2) stacks the panes on narrow screens; (3) makes the conversation scroll inside the left pane with the composer pinned to its bottom; and (4) replaces the plain input row with a rounded, multi-line, auto-growing composer in the normal UI font, with a round arrow send button inside the box at the bottom right, Enter to send, Shift+Enter for a newline, IME-safe, a quiet 1000-character counter, and Send disabled when empty. Front end only: no API, Python or contract change.

Scope

In scope

  • Rewrite the markup and styles of ChatComposer (box, auto-grow, round send button, counter, normal font).
  • A split layout for the chat page in ChatPage.jsx with a hide/show toggle for the suggestion pane, its tab-scoped persisted state, and its narrow-screen stacking.
  • The conversation scrolls inside the left pane; the composer is pinned to the pane's bottom (ChatThread scrolls the pane, not the page).
  • New CSS files and CSS tests; updates to the two existing assertions that encode the old vertical order; one runbook sentence.

Out of scope

  • Any change to /api/chat, /api/explain, /api/health, useChat.js, chatHistory.js, conversationStore.js, resultsSession.js or Python code (ADR-15, ADR-20, CC-19 unchanged).
  • Streaming text, Markdown rendering, copy buttons, message editing, attachments, a conversation list or sidebar of past chats, resizable (draggable) panes, dark mode.
  • Changing the chat copy (heading, empty prompt, starter questions, placeholder text) or the chat unavailable and no-session states.
  • The site header, footer, Layout.jsx, App.jsx, components.css, tokens.css, pairs.js: not edited here (the unapproved home-landing-page edits them; see "Edge cases & risks").
  • Real Voyager or model calls. All tests use the fake fetch and the offline fixtures fixtures/contract.json and fixtures/contract_agent.json; only the user runs the manual check against a real server (AC-22).

Design

Depends on ADR-17 (plain-JavaScript React, hash routing, no UI kit), ADR-18 (theme tokens, brand rules enforced by style-rules.test.js), ADR-29 (chat page, sessionStorage handoff) and ADR-20 (non-streamed verified answers). Adds ADR-33. Revises the layout decision U-7 of ui-polish-3 (see "Superseded text").

Decisions

IdDecisionWhy
D-1The page body is a CSS grid div.chat-split with two children in this DOM order: div.chat-column (left: conversation + composer) then section.chat-suggestion-panel (right: the suggestion). The page header (back link, h1, toggle button) sits above the grid.Visual order equals DOM order, so tab order and screen-reader order follow what sighted users see (WCAG 1.3.2, 2.4.3). Plain CSS, no JS width detection.
D-2Hide/show is a button in the header row, aria-expanded, aria-controls="chat-suggestion-panel", visible text "Hide suggestion" when open and "Show suggestion" when closed (same pattern as the "Show details" / "Hide details" toggle in FindPage.jsx). The panel is hidden with the hidden attribute and stays mounted.Removes it from the tab order and the accessibility tree; keeping it mounted preserves the "Why this match?" open state and its fetched explanation, so showing it again costs no request.
D-3When hidden, the grid gets the extra class chat-split-solo: one column, and the chat column is centered with a maximum width of 52rem.A full-width composer across 1100 px is hard to read; a centered column is the Claude-style focus mode.
D-4The panel state is persisted for the tab: sessionStorage key getwork.chat.panel.v1, value "open" or "closed", one value for all matches (not per match), default open. Module chatPanelPref.js. Not localStorage.A user who hides the panel wants it hidden when opening the next match's chat. sessionStorage is the storage the chat already uses (ADR-29) and the runbook already tells users about; the app uses no localStorage anywhere.
D-5Narrow screens (@media (max-width: 48rem)): a single column. The chat column comes first at a bounded height (clamp(24rem, 70dvh, 40rem), so the thread scrolls inside it and the composer stays at its bottom) and the suggestion panel stacks below it at natural height. The panel is open by default at every width; the toggle works at every width.CSS only, no matchMedia, no second default-state rule. Putting the suggestion first on a phone would push the conversation below the fold.
D-6Wide-screen height: .chat-split has the fixed height clamp(28rem, calc(100dvh - 22rem), 52rem) (with a 100vh fallback declaration first). 22rem approximates the header, title row, footer margin and footer. Both panes scroll internally.The shell is min-height based, so a flex chain cannot bound the main area; changing the shell would touch Layout.jsx and components.css, which another feature is editing. The constant may need a visual tweak (AC-22).
D-7The composer is form.chat-composer containing a rounded div.chat-composer-box; inside it the textarea on top and a bar below with the counter at the left and the round Send button at the right. The button keeps the accessible name "Send" through aria-label; its arrow is an inline SVG with aria-hidden.Matches the requested design and keeps every existing getByRole("button", {name: "Send"}) query working.
D-8Auto-grow combines two mechanisms: the existing rows attribute (one per newline, 1 to 6, kept because tests rely on it) and an inline pixel height from scrollHeight that also grows for soft-wrapped lines. CSS max-height: 9rem (6 lines at the 1.5 line height) caps it and overflow-y: auto scrolls beyond the cap.Rows alone never grow for one long wrapped line.
D-9Keyboard: unchanged rule, now stated as the contract. Enter without Shift sends. Shift+Enter inserts a newline. Enter is ignored (no send, no preventDefault side effect on the composition) when event.nativeEvent.isComposing is true or event.keyCode === 229 (Safari reports the Enter that confirms a composition with isComposing false and keyCode 229). Enter on an empty or whitespace-only draft, or while Send is disabled, does not call onSend and keeps the draft.The existing handler already does this; it is kept and extended with tests for the composition sequence.
D-10ChatThread scrolls its nearest .chat-scroll ancestor to the bottom (scrollTop = scrollHeight) when turns or status change; with no such ancestor it falls back to scrollIntoView({ block: "end" }) exactly as today.scrollIntoView also scrolls the window, which would make the page jump when the thread is inside a bounded pane. The fallback keeps all existing ChatThread tests valid.
D-11All new styling uses semantic tokens only, in two files: composer rules in the existing theme/chat.css, layout rules in the new theme/chat-split.css (imported by ChatPage.jsx). Text in --text-muted sits only on --surface (the tested contrast pairs in pairs.js; muted on --bg is not covered). No hex or rgb values, no box-shadow on any selector containing .btn or button, font-family only var(--font-stack), no px in font sizes (style-rules.test.js scans every CSS file). chat.css must not gain selectors matching .chat-turn other than .chat-turns, nor .chat { or .chat-log (chat-removal.test.js).Existing guard tests stay green without edits.

Data flow

ChatSession mount
  panelOpen = useState(loadPanelOpen)               // sessionStorage "getwork.chat.panel.v1", default open
  toggle click  -> setPanelOpen(!panelOpen); savePanelOpen(!panelOpen)
  panelOpen === false -> div.chat-split gets "chat-split-solo"; suggestion section gets hidden (still mounted)

User types in the composer
  draft state -> useLayoutEffect: textarea.style.height = "auto"; then = scrollHeight px when scrollHeight > 0
  Enter (no Shift, not composing, draft.trim() !== "" and not disabled) -> onSend(trimmed) -> setDraft("")
  onSend = useChat.send -> existing /api/chat flow (unchanged) -> turns update -> ChatThread effect scrolls .chat-scroll
